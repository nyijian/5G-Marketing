# 运行指南：每天采集与定期采集

本文说明这个工具日常怎么用：第一次怎么准备，每天跑什么，隔一段时间跑什么，结果去哪看，怎么设成自动运行。所有命令都在项目根目录 `D:\5GNet` 执行。

## 一、三种运行方式一览

| 场景 | 命令 | 日期窗口 | 预计耗时 | 用途 |
|---|---|---|---|---|
| 首次或补齐全年 | `pnpm collect:full` | 2026-01-01至今 | 约13分钟（实测） | 把全年数据补进数据库，一般只跑一次；新增信息源后再跑一次 |
| **每天** | `pnpm collect:daily` | 最近3天 | 约5分钟（实测） | 抓新公告，看“本次新发现” |
| 每周或补漏 | `pnpm collect --days 7` | 最近7天 | 比每日略长 | 周一补周末，或某天漏跑、失败后补采 |
| 指定时间段 | `pnpm collect --start-date 2026-10-01` | 指定日期至今 | 视窗口长度 | 月度复盘、专项排查 |
| 只出表、不联网 | `pnpm export` | 2026-01-01至今 | 几秒 | 用数据库里已有的数据重新生成全年清单 |

每次采集都会：

- 把新公告写入数据库 `data/5g-tender-monitor.sqlite`。同一公告重复采到只会更新，不会重复入库。
- **覆盖 `output/四川5G专网采购清单_最新.xlsx`。** 这是2026-01-01起的全年清单，并标出本次新发现的公告。**日常只看这一份即可。**
- 另存本次窗口清单：`output/四川5G专网采购清单_开始日期至结束日期.xlsx`，便于按日期留档。
- 更新运行摘要：`output/latest-run.json`。

窗口有重叠没关系，数据库会自动去重。所以每天用“最近3天”比“最近1天”更稳：公告晚收录、前一天失败或周末停跑，都不会漏。

## 二、第一次使用

```bash
pnpm install          # 安装依赖，只需一次
pnpm check            # 自检：类型检查＋自动化测试，全部通过即可
pnpm collect:full     # 补齐2026-01-01至今的数据
```

`collect:full`的作用：采购人官网（医院等）每个栏目最多翻100页，把全年公告补齐。省妇幼、泸州人医等官网发布量大，日常模式只翻10页，回溯不到年初。

## 三、每天怎么跑

### 1. 手动运行

```bash
pnpm collect:daily
```

跑完看命令行最后几行：

```
运行状态：success / success_zero / partial / failed
候选URL：…；详情成功：…；失败：…
纳入：…；待核实：…；排除：…
Excel（本次窗口）：D:\5GNet\output\四川5G专网采购清单_2026-11-23至2026-11-25.xlsx
Excel（全年最新）：D:\5GNet\output\四川5G专网采购清单_最新.xlsx
```

### 2. 打开Excel看什么

打开 `output/四川5G专网采购清单_最新.xlsx`：

1. **监测清单**：按“本次新发现”筛选“是”，就是今天新收录的公告。
   - “领文件状态”“递交状态”显示`未截止`的是还能参投的机会，已排在最前面。
   - 显示`未知`表示程序没解析出截止时间，采购人官网公告最常见，要点开原文看。尤其是近期发布的采购公告、比选公告。
   - “相关性判断”为`待核实`的要点开原文确认，很多要求写在附件里。
   - 发布日期较早、但“首次发现时间”是今天的，属于“补录/迟到发现”，不是今天才发布。
2. **运行与覆盖**：看每个平台和官网的状态。`partial`或`failed`表示那一路没跑完整，不能当成“今天没有项目”。
3. **未纳入候选**：被排除的公告和理由，用来检查有没有误判。

“最新”清单如果正在Excel里打开，程序会另存为 `…_最新_更新_时间.xlsx`，不会覆盖。所以运行前最好先关掉它。不联网、只想用数据库重新出一份全年表时，执行 `pnpm export`。

### 3. 设成每天自动运行（Windows任务计划程序）

项目里的 [`scripts/collect.cmd`](../scripts/collect.cmd) 会自己初始化fnm管理的Node环境，再执行采集，输出追加到 `output/collect.log`。

先确认脚本能找到Node和pnpm：

```bat
D:\5GNet\scripts\collect.cmd --check-env
```

然后在“命令提示符”或PowerShell中创建计划任务，每天07:30运行；如需配合08:10的“5G市场”日报，07:30开始正好留出余量：

```bat
schtasks /Create /TN "5G市场每日采集" /SC DAILY /ST 07:30 /TR "D:\5GNet\scripts\collect.cmd"
```

常用管理命令：

```bat
schtasks /Run    /TN "5G市场每日采集"     # 立即手动触发一次，检查是否正常
schtasks /Query  /TN "5G市场每日采集" /V /FO LIST
schtasks /Delete /TN "5G市场每日采集" /F
```

注意：

- 计划任务只在电脑开机、并且当前用户已登录时运行（以上命令的默认方式）。需要在未登录时也运行，可在“任务计划程序”图形界面里改为“不管用户是否登录都要运行”。
- 默认每天跑最近3天。想换窗口，把 `/TR` 改成 `"D:\5GNet\scripts\collect.cmd --days 7"`。
- 运行日志在 `output/collect.log`，失败时先看这里。

## 四、隔一段时间跑什么

| 频率 | 建议命令 | 说明 |
|---|---|---|
| 每周一 | `pnpm collect --days 7` | 补齐周末，同时复核上周状态为`partial`的来源 |
| 每月初 | `pnpm collect --start-date 上月1日 --max-pages 5 --site-pages 30` | 加大翻页，查漏补缺；再执行`pnpm export`出全年表 |
| 集团下发核验清单后 | `pnpm audit:historical` | 把集团清单与数据库对照，输出 `output/2026历史项目核验_平台分层.xlsx`，含平台、官网、第三方线索三张来源表 |
| 新增信息源后 | `pnpm collect:full` | 让新来源回溯全年 |
| 改过代码或配置后 | `pnpm check` | 确认测试全部通过 |

## 五、常用参数

| 参数 | 作用 |
|---|---|
| `--days 7` | 最近7个北京时间自然日（含今天） |
| `--start-date 2026-10-01` | 从指定日期开始（与`--days`二选一，都不写时从2026-01-01开始） |
| `--max-pages 5` | 政府采购、公共资源等平台每个关键词最多翻几页，默认2 |
| `--site-pages 30` | 采购人官网每个栏目最多翻几页，默认10；遇到早于开始日期的页面会自动停止 |
| `--output 文件.xlsx` | 指定Excel输出位置 |
| `--no-buyer-sites` | 本次不跑采购人官网 |
| `--no-tianfu` 等 | 跳过某个平台，完整列表见README“常用参数” |

## 六、常见情况

**运行状态是`partial`。** 有结果，但某些来源受限或没读完。常见原因：

- 天府阳光两站当前环境触发IP或滑块限制。
- 某个政府平台临时报错。
- 官网翻页到上限仍没覆盖到开始日期。

全量回溯（`collect:full`）时，下面两项是已知的、预期内的`partial`：

- 天府阳光按“专网”检索有几十页结果，默认只读2页；需要时可加 `--max-pages 10`。
- 泸州市人民医院列表第51页起服务器固定报错，最多回溯到3月上旬。

日常3天窗口一般不会碰到这两项。具体原因看Excel“运行与覆盖”表的“错误或限制”列。`partial`时不能对外说“今天没有项目”。

**Excel提示“正在被占用，已改存为…_更新_时间.xlsx”。** 目标Excel在Excel里开着，程序不会覆盖它，而是另存一个带时间戳的新文件。关掉旧文件后，下次运行会恢复正常文件名。

**某天漏跑了。** 下次运行时加大窗口即可，例如 `pnpm collect --days 7`。重叠部分会自动去重。

**想增加一家医院或单位的官网。** 在 `config/buyer-sites.json` 中仿照已有条目添加：

- 栏目地址：`lists`。
- 翻页模板：`pageUrl`，用`{page}`表示页码。
- 详情链接正则：`detailUrlPattern`。

然后运行 `pnpm check`，再执行 `pnpm collect --days 30 --site-pages 30` 验证能否抓到。

**第三方网站（采招网、千里马等）看到的项目。** 这些站不自动采集。人工找到线索后，到招标平台或采购人官网找原文；找到新的发布站点时，登记进 `config/source-catalog.json` 或 `config/buyer-sites.json`。

## 七、文件在哪里

| 文件 | 内容 | 是否上传GitHub |
|---|---|---|
| `output/四川5G专网采购清单_最新.xlsx` | **全年最新清单，每次采集后覆盖** | 否（本地） |
| `output/四川5G专网采购清单_日期区间.xlsx` | 每次采集窗口或导出的留档清单 | 否（本地） |
| `output/latest-run.json` | 最近一次运行摘要 | 否 |
| `output/collect.log` | 计划任务运行日志 | 否 |
| `output/2026历史项目核验_平台分层.xlsx` | 集团清单核验结果 | 否 |
| `data/5g-tender-monitor.sqlite` | 全部历史采集数据，**请定期备份** | 否 |
| `config/*.json` | 关键词、范围、信息源台账 | 是 |

数据库和结果文件只保存在本机，不会随代码推送到GitHub。
